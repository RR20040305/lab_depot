# Сервис учёта лабораторного оборудования (lab_depot)

## Назначение

Приложение для учёта оборудования в лабораториях: хранение информации о каждом устройстве, отслеживание его текущего состояния, сроков выдачи и ответственных сотрудников. Помогает избежать потерь, упрощает поиск и контроль за техническим обслуживанием.

Проект развивался по этапам:
- **ПР1–ПР2** — консольное приложение на функциях и словарях;
- **ПР3** — перевод на объектную модель (классы `Equipment`, `Employee`, `Laboratory`, `Issue`);
- **ПР5** — добавление веб-интерфейса на Django.

После ПР5 у проекта **две рабочие версии** — консольная (`main.py`) и веб-версия (`manage.py`). Они используют общую объектную модель и одни и те же JSON-файлы.

## Используемые технологии

- Python 3
- Django 5.2 — веб-фреймворк
- HTML — разметка веб-страниц
- CSS и Bootstrap 5.3 — оформление страниц
- pytest — автоматизированные тесты
- flake8 — проверка качества кода

## Целевая аудитория

Сотрудники лабораторий (научные работники, инженеры), заведующие лабораториями, администраторы, отвечающие за материально-техническую базу.

## Предметная область

Учёт оборудования в научных или производственных лабораториях. Включает инвентаризацию, перемещение оборудования между лабораториями, выдачу во временное пользование, фиксацию ремонтов и списаний.

## Основные сущности

### Equipment — оборудование
- Атрибуты: `inv_num` (инвентарный номер), `name` (название), `status` (состояние: `исправно` / `в ремонте`).
- Методы: `is_available()`, `matches()`, `__str__()`.

### Employee — сотрудник
- Атрибуты: `emp_id` (табельный номер), `fio`, `position` (должность), `lab` (номер лаборатории).
- Методы: `matches()`, `__str__()`.

### Laboratory — лаборатория
- Атрибуты: `lab_id` (номер), `responsible` (ответственное лицо), `location` (местоположение).
- Методы: `matches()`, `__str__()`.

### Issue — выдача оборудования
- Атрибуты: `id`, `equipment` (объект `Equipment`), `employee` (объект `Employee`), `return_date`, `status` (`активна` / `завершена`).
- Методы: `cancel()`, `is_active()`, `__str__()`.
- **Взаимодействие объектов**: `Issue` связан с `Equipment` и `Employee` через ссылки, а не через идентификаторы. В JSON сохраняются только идентификаторы (`inv_num`, ФИО), при загрузке выполняется поиск соответствующих объектов.

## Страницы веб-интерфейса

| URL | View-функция | Назначение |
|---|---|---|
| `/` | `homepage.views.index` | главная страница, навигация по разделам |
| `/equipment/` | `equipment.views.equipment` | список оборудования |
| `/equipment/<str:inv_num>/` | `equipment.views.equipment_detail` | карточка оборудования, статус «выдано/доступно» |
| `/laboratories/` | `laboratories.views.laboratories` | список лабораторий |
| `/laboratories/<str:lab_id>/` | `laboratories.views.laboratory_detail` | карточка лаборатории |
| `/employees/` | `employees.views.employees` | список сотрудников |
| `/employees/<str:emp_id>/` | `employees.views.employee_detail` | карточка сотрудника |
| `/issues/` | `issues.views.issues` | список выдач |
| `/issues/<int:issue_id>/` | `issues.views.issue_detail` | карточка выдачи со ссылками на оборудование и сотрудника |

Страницы с динамическими URL возвращают код `404`, если объект с указанным идентификатором не найден. Для любого другого несуществующего адреса срабатывает собственная страница `handler404`.

## Реализованные функции

### Используются в веб-интерфейсе (ПР5)
- Просмотр списка оборудования
- Просмотр карточки оборудования со статусом «выдано/доступно»
- Просмотр списка лабораторий
- Просмотр карточки лаборатории
- Просмотр списка сотрудников
- Просмотр карточки сотрудника
- Просмотр списка выдач
- Просмотр карточки выдачи со связанными объектами
- Обработка ошибки 404

### Доступны только в консольной версии (ПР3)
Эти операции реализованы в `main.py` и работают с JSON. В веб-интерфейсе они появятся после добавления форм и POST-запросов:
- Добавление, редактирование, удаление оборудования
- Добавление, редактирование, удаление лабораторий
- Добавление, редактирование, удаление сотрудников
- Оформление и отмена выдач
- Поиск и сортировка
- Статистика

## Хранение данных

Данные хранятся в JSON-файлах в папке `data/`:
- `data/equipment.json` — оборудование
- `data/employees.json` — сотрудники
- `data/laboratories.json` — лаборатории
- `data/issues.json` — выдачи

При загрузке JSON-данные преобразуются в объекты `Equipment`, `Employee`, `Laboratory`, `Issue` (через `from_data()` и `load()`). При сохранении объекты преобразуются обратно в JSON (через `to_dict()` и `save()`).

Модуль `storage.py` устойчив к трём кодировкам (`utf-8-sig`, `utf-8`, `cp1251`) — файл, случайно сохранённый в Windows-1251, всё равно прочитается корректно. При записи файлы всегда сохраняются в UTF-8.

## Назначение модулей

### `main.py`
Консольная версия приложения (сохранена с ПР3). Отвечает за меню, ввод данных, организацию пользовательских сценариев.

### `labdepot/`
Пакет настроек Django-проекта:
- `settings.py` — настройки проекта;
- `urls.py` — маршрутизация верхнего уровня, `handler404`;
- `asgi.py`, `wsgi.py` — точки взаимодействия с сервером.

### `homepage/`
Django-приложение, отвечающее за главную страницу и обработку 404:
- `views.py` — функция `page()` (общий HTML-каркас) и view-функции `index()` и `page_not_found()`;
- `urls.py` — маршрут главной страницы.

Функция `page()` размещена здесь, потому что главная страница задаёт общий вид остальных страниц. Остальные Django-приложения импортируют её.

### `equipment/`, `laboratories/`, `employees/`, `issues/`
Django-приложения для соответствующих разделов. Каждое содержит:
- `views.py` — view-функции для списка и карточки объекта;
- `urls.py` — маршруты приложения;
- `models.py` — Django-модели (заполняются в следующих работах).

### `models/`
Классы предметной области и функции работы с ними (пакет ПР3):
- `equipment.py` — класс `Equipment` и функции работы с оборудованием;
- `employees.py` — класс `Employee` и функции работы с сотрудниками;
- `laboratories.py` — класс `Laboratory` и функции работы с лабораториями;
- `issues.py` — класс `Issue` и функции работы с выдачами.

### `storage.py`
Отвечает за загрузку и сохранение данных. Выполняет преобразование JSON ↔ объекты Python. Устойчив к трём кодировкам.

### `utils.py`
Вспомогательные функции: `parse_date()`, `is_future_or_today()`, `validate_status()`.

### `tests/`
Автоматизированные тесты проекта (27 тестов).
